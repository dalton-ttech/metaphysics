# 安全与盲测威胁模型

## 需要防止的泄漏

1. 提问方直接读取某人的事件真值；
2. 通过无限提问枚举完整人生；
3. 重复问题或重开会话平均掉回答噪声；
4. 在提交画像后继续追问；
5. 在独立验证尚未结束时取得单人得分；
6. 修改历史回答、预测或实验配置；
7. 根据公开随机种子重建隐藏样本。

## 权限角色

- `admin`：启动实验、签发批次、关闭批次和取得整批报告；
- `interviewer`：只能列出自己批次内的会话、逐题询问、提交预测；
- `auditor`：只读查看配置哈希、密文哈希和审计链状态；
- 无令牌：仅健康检查。

## 技术控制

- 生成种子与 AES-256-GCM 主密钥由密码学安全随机源产生；
- 主密钥不落盘，单记录密钥通过 HKDF 派生；
- 每个密文使用独立随机 nonce，并绑定 profile id 与模型版本作为 AAD；
- interviewer 令牌只作用于一个批次，令牌仅存哈希；
- 问题必须来自冻结题库，每个会话最多 24 个唯一问题；
- 完成至少 18 问后才能提交，提交后不可恢复；
- validation 批次只返回整批聚合结果，不返回逐人真值；
- 每次操作进入 SHA-256 前向哈希链；
- 题库、配置、代码和密文均写入实验清单。

实验协调器把管理员令牌只保留在父进程，并仅向 interviewer 子进程发送批次级令牌。回答噪声由隐藏种子派生，便于事后重放；隐藏种子在实验期间不落盘，全部预测锁定后才写入 Git 忽略的 `reveal/`。

## 明确不承诺的边界

本设计防止普通提问客户端和受限 Agent 获得真值，不声称能够对抗拥有管理员权限、进程内存读取能力或修改 Oracle 源码的本机攻击者。若用于外部对抗性评测，应把 Oracle 部署到独立账户、容器或远程主机。
