# v1.1 与 v2.2 对比

## 核心变化

| 项目 | v1.1 | v2.2 |
|---|---|---|
| 问题结构 | 18—24 道，同一会话固定 1/2/3 事件题型 | 固定 24 道：16 道三事件全覆盖、4 道低频交叉、4 道重复单项确认 |
| 事件覆盖 | 自适应选择，可能有事件未被问到 | 48 个事件每人至少覆盖一次，10 个弱项再覆盖一次 |
| 社媒数据 | 未结构化进入题目证据 | 14 条脱敏模式、4 条跨来源事件链；只用于本体和措辞 |
| 高置信校准 | 目标 Precision ≥90% | 校准目标 Precision ≥95%，验收仍为 ≥90% |
| Oracle | v1.1 独立冻结 | v2.2 独立 Oracle，支持混合题型和解封后诊断 |

## 正式独立验证

两个版本使用不同隐藏种子，因此下表适合观察工程方向，不是同样本因果实验。

| 指标 | v1.1 | v2.2 | 变化 |
|---|---:|---:|---:|
| 高置信 Precision | 93.5% | 94.7% | +1.2 个百分点 |
| 候选 Precision | 52.9% | 45.0% | -7.9 个百分点 |
| 候选 Recall | 68.2% | 82.3% | +14.1 个百分点 |
| 候选 F1 | 59.6% | 58.2% | -1.4 个百分点 |
| Brier | 0.112 | 0.125 | 变差 0.013 |
| 平均题数 | 22.4 | 24.0 | +1.6 题 |
| 复测 Jaccard | 87.8% | 93.3% | +5.5 个百分点 |
| 模拟理解率 | 95.6% | 96.1% | +0.5 个百分点 |
| 零召回事件 | 多个 | 0 | 消除 |

## 产品决策

v2.2 不应替换成“所有候选都算命中”的展示。它主动用一部分候选 Precision 换取重大事件召回，因此必须保留用户逐条确认层。高置信事件可以直接进入画像草稿；候选事件只能作为可核验陈述出现。

若产品场景更重视少误报而不重视漏项，应切换到 `adaptive_control`；若场景是先尽量找齐重大经历、再由本人验真，则使用 `targeted_verify`。当前铁板神术流程采用后者。
