# 铁板神数真实流程与定度数学调研 V3

日期：2026-07-21

## 一、结论

本轮需要推翻上一版的核心产品模型。

铁板神数不应被产品化为“用诗意句子包装的多事件问卷”。其最有辨识度、也最值得复刻的体验是：

> 四柱起例 → 起数 → 按数启卷 → 读取固定条文 → 命主判应或不应 → 复算换数 → 考刻定分 → 再取一生条文 → 编成命书

用户感受到的应是“术者在寻找唯一出生刻分”，而不是“系统正在收集人生画像”。后台可以使用现代概率模型、主动学习和纠错编码，但前台必须保持数序、卷册、错条、复算、落刻和命书之间的因果连续性。

“正统”在公开网络资料中不存在唯一可核验版本。现有资料在江南、岭南、北派、邵子、皇极等名称、刻分算法、秘数与卷数上互有冲突。因此产品应采用“可感知的传统共同流程”，并在内部明确自己的底本版本，不宣称破解唯一古法。

## 三、用户提供的视频实际讲了什么

字幕中的流程可以整理为以下四段。

### 1. 四柱与初始刻数

- 输入出生年、月、日、时。
- 天干地支按太玄数配数。
- 通过总数、时支序数、除数和余数等方式先得到一个初始刻位。
- 一时辰分八刻，每刻十五分钟。

这一步更像“生成搜索起点”，不是直接完成定刻。

### 2. 六亲考刻

视频列出三类方式：

1. 由四柱太玄数先求一刻，再用父母寿夭、兄弟人数与排行检查。
2. 年月柱起先后天卦，得到四位基数；条文不合则加 `1327` 的某种倍数继续查，命中后以该数作为后续推命基础。
3. 反过来使用父母或兄弟姐妹的生肖、六十甲子生年，通过乾坤甲流度等表找到数序；例如父命条从 `9003` 一带逐十变化，直到父亲的实际干支吻合。

### 3. 由命中的基数继续取条

- 命中的数序再次化卦。
- 先天卦和后天卦分别形成基数。
- 按 `+96` 或 `-96` 连续取得若干条文。
- 视频把前后卦合计的八条称为一生重要信息的一部分。

### 4. 大运与流年

- 排出大运流年。
- 以月、日、时、年的干数与运干、运支组合取数。
- 查相应条文作为某步大运或流年的主要事件。
- 最终按顺序整理为命书。

### 视频本身的限制

字幕存在多处疑似识别或口述错误，例如“时支序数是乙”“我居次却解释为老三”等，不能直接把字幕公式写进生产代码。正确做法是把字幕当作流程线索，再用底本页、表格和多套实例逐项核对公式。

## 四、条文风格修正

用户提供的扫描页说明，铁板原条的主要气质不是含混诗意，而是：

- 竖排、编号、表格式索引。
- 句子短，省略主语和虚词。
- 大量使用“父、母、妻、子、兄弟、某岁”等硬实体。
- 语气断定，常见“方合此刻”“定在此年”“姻缘前定”等结尾。
- 可一条包含两项相互关联的六亲事实。
- 对生死、刑克、婚姻和子嗣直言不讳。

倪匡公开命文也呈现两种不同语体：

1. **考刻硬断**：兄弟人数、排行、父母生肖、婚龄、妻子年龄差，文字直接而短。
2. **命书辞章**：人生总评、性情、朋友、后运常使用对句和隐喻，含混度更高。

因此产品不应再强迫所有条文使用一种“现代汉语诗体”。新内容体系应分成四类：

| 类别 | 功能 | 文体 |
|---|---|---|
| 考刻条 | 校验父母、兄弟、配偶、子女和早年硬事实 | 极短、直接、斩钉截铁 |
| 定分条 | 区分相邻分钟或刻位 | 两到四个同域事实组成一条 |
| 命局条 | 描述性格、总运与人生格局 | 对句、口诀、半文半白 |
| 运限条 | 对应年龄、大运或流年 | 年龄在前，事件断语在后 |

“司刻解释”不应每条都出现。条文本身已经直白时，用户直接判断即可；只有遇到“椿萱、棠棣、鼓盆”等旧词时，才由司刻者给出一句短注。解释者是辅助原典，而不是把每条条文重新翻译成现代问卷。

## 五、倪匡案例对产品流程的关键启发

较早的自述转录给出的实际节奏是：

1. 桌上先有十二本、每册约一千条的“天书”。
2. 用户报出生日期和大约时间。
3. 大师从 12:30 对应的数开始算。
4. 用户亲自按数翻出条文。
5. 第一条不合，再算下一条；连续数条不合。
6. 到第七次，即 12:37，对应条文命中。
7. 定刻以后才正式继续批出六亲、婚姻、朋友、嗜好和运限条文。
8. 当场约得三十条，余下整理后寄出。

这说明其体验并不是二分查找。外观上更接近**候选分钟的顺序检验**。前面那些“不合”的条文本身也在产生信息，但用户把它们理解为排除错误出生分钟，而不是在回答问卷。

产品应复刻这一心理结构：

- 先显示一个由出生资料起出的数。
- 数指向一本既存命籍中的一条。
- 用户判定“应 / 不应”。
- 不应时该数被撤掉，算盘重新起数。
- 应时只表示候选刻位变强，不一定立刻停止。
- 三个独立六亲域均有命中，且没有关键矛盾，才可以落刻。

## 六、与吠陀占星出生时间校正的关系

用户的判断在数学抽象上成立：两者都属于**用已发生事件反推隐变量出生时间**的问题。

但两套传统技术并不相同：

| 维度 | 铁板神数考刻 | 吠陀占星出生时间校正 |
|---|---|---|
| 候选对象 | 某时辰内的刻、分或数序 | 出生时间对应的上升度数与分盘 |
| 主要证据 | 父母、兄弟、配偶、子女等六亲硬事实 | 婚姻、职业、迁移、子女、疾病等有日期人生事件 |
| 传统映射 | 配数、起卦、秘数、编号条文 | 上升、分盘、大运、行运等 |
| 用户所见 | 数序与固定条文 | 多张候选星盘与事件吻合度 |
| 输出 | 定刻后的编号命书 | 校正后的出生时间与星盘 |

现代吠陀产品常以 4–8 个有日期事件扫描候选时间，并用大运、分盘和行运对每个候选打分。[VedicDream 示例](https://www.vedicdream.com/home/birth-time-rectification)、[Parashara's Light 软件说明](https://www.parasharasoftware.com/Parashara-Light-90/features/tools/changeTime.aspx)

“四分钟”更准确的天文学解释是地球约四分钟自转一度，因此上升点约每四分钟移动一度；这并不意味着所有吠陀流派都统一以四分钟为最终精度。分盘和具体算法可能要求更细或更粗的时间。[中文节目说明](https://www.xiaoyuzhoufm.com/episode/68be4f5a9eb4a49300507b7d)

可借鉴的不是星盘视觉，而是其算法思想：将每个候选出生时间生成一套结构，再用多个有日期、可验证的事件联合打分。职业占星实践也强调单凭三四件事可能只是巧合，应区分事件的重要性并逐个对照候选盘。[生时校准实践说明](https://www.ridleydetaipei.tw/product/birth-time-rectification/)

## 七、现代数学模型

### 1. 隐状态

设候选出生分钟为：

`T = {t1, t2, ..., tn}`

用户给出一个时辰时，默认有 120 个一分钟候选。第一层可以先分成 30 个四分钟度区，选出度区后再区分内部四分钟。

### 2. 条文不是随机问题，而是候选时间的固定产物

每个候选时间通过可重放的“数序显示层”生成：

`产品版本 + 四柱种子 + 候选刻位 + 条文ID → 数序 / 卷号 / 条号`

这一映射必须确定、可复盘。同一版本、同一出生资料、同一候选时间和同一条文，应得到相同数序。太玄配数、先后天卦、`±96`、八卦滚等公开算法可以成为不同显示版本，但在无法证明其历史有效性前，不应限制现代推断引擎的准确率。现代算法负责选条和收敛，数序层负责把结果稳定地表现为“起数查卷”。

### 3. 带噪声的贝叶斯更新

对于条文 `q` 和回答 `y ∈ {应, 不应, 未明}`：

`P(t | y, q, D) ∝ P(y | t, q) · P(t | D)`

条文可能只部分相合，用户也可能记不清，所以不能一次“不应”就永久删除候选。不同条文需要不同的误报率、漏报率和可回忆度。

### 4. 主动选条

后台从当前候选允许的条文中选择预期信息增益最大的条，同时扣除：

- 连续重复同一六亲主题的惩罚。
- 过于明显暴露采集目的的惩罚。
- 高基础发生率、低区分度条文的惩罚。
- 过多负面条文的节律惩罚。
- 同一原条反复曝光的惩罚。

形式上可写为：

`utility(q) = expected_information_gain(q) - repetition - obviousness - fatigue - corpus_exposure`

### 5. 纠错与停止

产品不以一条命中定刻，而以跨域冗余实现纠错：

- 至少三个独立证据域：父母、兄弟、配偶/子女或早年节点。
- 第一候选与第二候选的概率差达到阈值。
- 最后追加两条不参与初筛的封存确认条。
- 若两条确认失败，则回到候选集合，不强行落刻。

### 6. 第一轮实验参数

这些是待模拟验证的起点，不是最终产品常数：

- 已知时辰、120 分钟窗口：先分 30 个四分钟度区，再精分到一分钟。
- 理想无噪声下，区分 30 个度区至少需要 5 比特，区分区内 4 分钟再需 2 比特。
- 考虑回答噪声、条文不均衡和仪式节律，建议 9–14 条主考刻条。
- 再用 3–4 条封存确认条，首版总交互量为 12–18 条。
- 时间范围超过两小时或用户大量选择“未明”时，可扩展到 18–24 条。
- 前台不显示总题数，只显示“初起、复算、刻渐明、刻成”。

## 八、条文库的新数据结构

上一版的三事件 OR 问题库应停止扩充。新条文库至少包含：

```text
edition_id             底本版本
source_image_ref       原页或扫描定位
volume_no              卷号
clause_no              条文编号
raw_text               原始字形文本
normalized_text        校勘后的文字
clause_type            考刻 / 定分 / 命局 / 运限
fact_atoms             可核验事实原子
predicate              应验判定规则
age_window             适用年龄或年份
kin_domain             父母 / 兄弟 / 配偶 / 子女等
answerability          用户可否明确回忆
base_rate_band         现实基础发生率档位
candidate_time_links   允许关联的候选刻分
source_status          原本 / 转录 / 自编 / 待校
rights_status          授权状态
checksum               版本校验
```

规模建议：

- 流程验证：30–50 条，只验证交互和起数逻辑。
- 算法 MVP：至少 200–300 条高区分考刻条，加 400–700 条命局/运限条。
- 正式产品：导入并校勘一个完整、可授权的条文版本；若以万二条体系为锚点，目标即完整的约 12,000 条索引，而不是由模型临场伪造原文。

## 九、必须保留的诚实边界

产品可以复刻传统流程，并在内部使用现代算法提高前半生识别率；但需要区分三件事：

1. **历史底本原文**：只能来自有出处的版本。
2. **校勘与现代批注**：可以由编辑和模型完成，但不能冒充古本原句。
3. **自编补条**：可以加入固定、版本化语料库，但内部必须标为编纂条文，以便测试、回滚和替换。

这不是为了在用户页面解释技术，而是为了保证产品长期可维护，避免不同版本、不同模型和不同日期生成互相冲突的“古条”。

## 十、下一阶段研究缺口

1. 取得用户扫描页所属书名、卷次或更多连续页，确认顶端一至九数字的索引规则。
2. 找到《灵界轻探》对应章节的可靠纸本扫描，核对转载是否完整。
3. 选择一个产品锚点版本：江南万二条、岭南命书体系，或明确命名的现代编纂本。
4. 对字幕中的太玄配数、`1327`、`±96` 和父母甲流度公式逐项制作可重放算例。
5. 在新的候选时间模型上重跑密封真人代理模拟，不复用旧的三事件问卷结果。
