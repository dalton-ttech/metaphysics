# V5 命理产品市场与体验机制调研

调研日期：2026-07-22

## 一、市场不是在卖“算得更多”，而是在卖五个可持续对象

### 1. 身份对象

The Pattern 把结果组织为 `Your Pattern`，Daoly 用 Pine Tree、Sun、Mountain 等日主原型命名用户。身份对象的价值是让用户能用一句话记住结果、反复解释自己，并自然分享。

### 2. 时间对象

The Pattern 的 timing cycles、CHANI 的 transits 与 key dates、中文八字产品的大运流年，都是把一次性报告变成持续回访的时间结构。

### 3. 关系对象

The Pattern 的 Bonds、Co–Star 的关系入口、中文市场的合盘/合婚，使产品天然具有“再带一个人进来”的增长结构。

### 4. 解释角色

Sanctuary 把体验做成与可信赖占星师对话；线下寺庙求签则由解签人把含混签文放入求签者的情境。用户需要的并非更多说明文字，而是一个稳定角色替符号系统完成解释。

### 5. 回访仪式

每日运势、一次一卦、日记和关键日期提醒，构成低成本回访。它们之所以有效，不只是推送，而是用户每次完成一个具有象征意义的小动作。

## 二、中文市场的有效做法与失败信号

### 有效做法

- 问真八字：专业排盘、真太阳时、流年判断一目了然，建立“计算严谨”的信任。
- 准了：占星、八字、紫微、关系、真人、AI、社区组合，证明关系与内容广度能带来高频入口。
- 橡子星座：大量解释内容与真人咨询，缩短“看不懂盘”到“有人替我解释”的距离。
- 新一代工具：强调不注册、真太阳时、双重格局校验、只输出高置信结论，说明“可见的克制”也能成为专业感。

### 失败信号

- 只给排盘、不做解释：用户觉得专业但难用。
- 体系堆得过多：入口多但品牌心智模糊。
- 付费墙过早或每一层都收费：准确性还未被证明，信任先被打断。
- 生成速度慢：长报告的等待会消耗仪式感。
- 泛化套话：即使短期产生共鸣，也会在用户对比或复玩后暴露模板感。

## 三、“用户觉得说的就是我”的心理机制

这不是单一的巴纳姆效应，而是六种机制叠加：

1. **个人验证**：人会把普遍描述当作针对自己的准确描述。
2. **确认偏误**：命中的条目比未命中的条目更容易被记住。
3. **自我参照效应**：与自我关联的信息编码更深、回忆更强。
4. **高显著旧事**：少数可核验且情绪显著的事件，会为整套系统建立可信度。
5. **仪式权威与沉浸**：重复动作、等待、封印、固定文本和解释角色让结果显得有来源、有秩序。
6. **共同完成意义**：用户并非被动接收，而是在“应/不应”和回忆中参与构造自己的一生叙事。

产品不能只依赖前三项。只用模糊共性会迅速被识别为套话。可靠路径是：

- 先命中 3—5 个具体而显著的锚点；
- 再用这些锚点连接出一条用户未直接说出的生命主线；
- 最后给出一个可观察、可记忆的身份结论和未来应期。

## 四、铁板神数形式中真正有产品价值的部分

传统叙述中的核心流程不是“连续做选择题”，而是：

1. 以生辰大概时段起出相邻刻位；
2. 每个刻位对应固定数与固定条文；
3. 用六亲和已发生旧事校验刻位；
4. 相邻刻位逐步排除；
5. 定刻后以同一数序开出整卷命书。

现代实现不必声称复原失传算法，但必须保留用户可感知的因果链：

`生辰种子 → 候选刻位 → 固定条文 → 旧事判验 → 相邻刻排除 → 旁证 → 定刻 → 命书`

当前产品最缺的不是古籍字体，而是让这条因果链在界面上发生。

## 五、GitHub 工程案例的启示

- `iztro`：把紫微斗数排盘、十二宫与运限做成确定性计算层。
- `ZiweiKnows`：计算、AI解释、流年、人生K线与分享卡分层。
- `suangua`：计算引擎、API、LLM 与古籍 RAG 分离。
- `VedAstro`：将事件定义为数据与规则随时间的组合，并允许把真实人生事件记录回时间轴。

适合本项目的工程原则：

1. 候选刻位、数序、事实映射必须确定性可重放。
2. 大模型只负责受约束的叙事合成，不负责偷偷改变事实。
3. 每条输出必须能回溯到候选画像、事实节点和证据条文。
4. 事实图与表达层分开，避免“问题原句直接进入命书”。

## 六、产品机会

产品不应定位成“又一个 AI 算命报告”，而应定位为：

> 一场可以收藏的数字考刻仪式：以旧事校准刻分，由司刻人开出一卷只属于此人的命书。

核心传播句不是“我们有很多命理算法”，而是：

> 它先说中你已经走过的三件事，才肯开口说以后。

这同时解决专业感、神秘感和传播记忆点。
