# 铁板神数体验重构 PRD V3

日期：2026-07-21

## 1. 产品重新定义

### 一句话定义

以固定条文命籍和现代定度算法为核心，为用户完成一次可感知的铁板神数“考刻定分—启卷批命—命书成册”体验。

### 核心承诺

用户不是来完成性格测试，也不是来阅读 AI 分析报告。用户只需要：

1. 提供出生年月日、出生地和大概时段。
2. 按数启阅一条条既存条文。
3. 判断条文“应”或“不应”。
4. 见证系统定出精确出生刻分。
5. 获得一部由编号条文、现代解读和人生时间轴组成的命书。

### 旧模型退场

以下设计不再进入新版主流程：

- 24 道三事件组合题。
- 8 道意图明显的单事件验真题。
- “只要三象中有一象发生就点是”的 OR 规则。
- 固定总题数和普通进度条。
- 用户主动选择事业、感情等关注方向。
- 把概率、候选画像、证据标签直接解释给用户。
- 用泛化人格句替代六亲和年龄硬断。

## 2. 产品双层结构

### 用户可见：铁板仪式层

`报时 → 排盘 → 起数 → 启卷 → 判条 → 复算 → 落刻 → 批命 → 成书`

### 用户不可见：现代推断层

`出生时间候选 → 固定条文映射 → 回答似然 → 贝叶斯更新 → 主动选条 → 冗余确认 → 命书编纂`

现代算法负责“下一条选什么、候选刻位如何更新、何时足够确定”；传统流程层负责把这一过程显示为可重放的起数、查卷和变数。数序由版本、四柱种子、候选刻位和条文 ID 确定性生成，不需要假装已经破解唯一古法。

## 3. 新版用户流程

### 阶段一：入局

输入项只保留：

- 姓名或称谓，可选。
- 性别。
- 公历/农历出生日期。
- 出生地点。
- 大概出生时段，允许精确时间或范围。

不再询问“想重点看什么”“选择文案风格”等产品设置。

### 阶段二：排盘与初起

- 系统完成时区、夏令时和真太阳时所需的内部换算。
- 屏幕依次落下四柱，不出现解释性长文。
- 算盘开始起数，最终停在四到五位数。
- 显示“某卷·某条”，用户执行一次启卷动作。

### 阶段三：考刻定分

每轮固定节奏：

1. 算珠移动，数序出现。
2. 对应纸页或条签被取出。
3. 显示原条；旧词必要时才出现一行司刻短注。
4. 用户按 3D 实体键“应 / 不应”；“未明”作为弱按钮。
5. 不应：条页退入废条区，数序撤回，重新起数。
6. 应：朱印落下，候刻范围收紧，再取下一条。

前台不显示“第几题”，只显示四种仪式状态：

- 初起
- 复算
- 刻渐明
- 刻成

### 阶段四：落刻

落刻是第一处震撼点，整屏只显示：

```text
午时四刻
十二时三十七分
命籍既定
```

同时保留一条可展开的“考刻印记”，只列卷号、条号和应验印，不展示算法解释。

### 阶段五：启命

定刻后才进入正式批命。系统依次起出：

- 六亲与家门。
- 婚姻与子息。
- 前运关键年龄。
- 事业财帛。
- 大运与后程。

其中已发生的硬断可以继续让用户“收录 / 撤条”，但不再出现一个独立的“八项验真”阶段。交互应像命书正在被编定，而不是二次问卷。

### 阶段六：命书成册

命书建议分五卷：

1. **定刻卷**：四柱、定刻结果、命籍编号。
2. **六亲卷**：父母、兄弟、配偶、子女等条文。
3. **前运卷**：按年龄排序的已发生节点。
4. **今局卷**：当前三到五年的主局。
5. **后程卷**：按大运或时间窗排列的明确断语。

每个节点由三层组成：

- 编号原条。
- 司刻批注。
- 年龄/年份、事件和后果的现代命书正文。

## 4. 单条页面 UI

### 页面结构

```text
顶部：午时 · 刻未定                         卷三

                     9467

               兄弟四人，我居三

              [必要时：司刻短注]

          ┌────────┐  ┌────────┐
          │   应   │  │  不应  │
          └────────┘  └────────┘
                    未明
```

### 视觉原则

- 延续浅色底，但从“现代文化杂志”转向“被数字唤醒的古籍台案”。
- 参考用户扫描页的米白纸、黑墨、粗框、竖排与大留白；朱砂只用于命中印和“应”键。
- 不使用卡片套卡片。
- 原条可以竖排；操作和现代批注保持横排，避免阅读障碍。
- 数序不是装饰，必须与每次起数、启卷和历史记录一致。
- 算盘需使用真实生成或拍摄资产，不能以普通圆点动画假装。
- “应 / 不应”继续使用用户指定的 3D 实体按键；按下深度、阴影和回弹体现物理感。

### 动效与声音

- 起数：算珠连续移动 0.8–1.5 秒，声音由密到疏。
- 数定：最后一颗珠停下后，编号才显现。
- 启卷：纸页沿真实折页轴展开，不使用普通卡片淡入。
- 应：短促木印声，朱印在 180–260ms 内完成。
- 不应：无失败红色提示，纸页退回、算珠复位。
- 支持关闭声音与减少动效。

## 5. 原条与解释者

### 原条优先

直接条文不解释：

> 父命甲子年生方合此刻

> 兄弟五人我居三

> 二十五岁洞房花烛之年

含旧词条文才解释：

> 椿花光南极，萱草庆北堂

司刻短注：此条问双亲俱在。

### 司刻者规则

- 无头像、无聊天气泡、无自我介绍。
- 只在启条后、用户需要时出现。
- 每次最多一句解释和一句判定提示。
- 不说概率、数据、画像和模型。
- 不把条文扩展成三个互不相关的现代事件。

## 6. 命书的震撼结构

### 前运节点示例

```text
条一〇八三七
二十五岁，去旧门而入新途。

二十四至二十六岁之间，原有的学业或职业路径中断；
你随后离开熟悉环境，在新的城市或行业重新开始。
这次转向也使你与原来的一段关系逐渐疏远。
```

### 后程节点示例

```text
条七九六四
职位先动，财路后开。

三十七至三十九岁，合作或上级结构会先有一次更替；
旧位置难以久留，随后九个月内有跨地域项目接上。
财不暴起，但现金流会先稳。此期忌替关系人担保。
```

后程不再同时罗列迁居、转行、创业、感情四种可能。每条只保留一个主事件、一个触发条件和一个结果。

## 7. 当前代码迁移决策

### 可以保留

- 浅色宣纸基调。
- 3D “是 / 否”按键的物理交互基础。
- 命书长卷式排版基础。
- 已有测试、密封模拟和数据隔离框架。
- 移动端优先和减少动效支持。

### 需要替换

- `questions.ts` 中三事件组合题与单事件追加题。
- `BASELINE_TURNS = 24` 和固定追加八问的状态机。
- `eventIds` OR 概率更新。
- 页面上的阶段进度条、题号和工程解释。
- 泛化性格候选与“你确认了 N 段旧迹”的结果页。
- 没有真实编号来源的“研究条”前台呈现。

### 新模块

- `calendar-engine`：历法、时区、真太阳时和四柱。
- `numbering-display`：可重放的数序、卷号和条号；可挂接太玄配数、先后天卦、八卦滚等不同传统显示版本。
- `traditional-formula-lab`：隔离验证公开公式及测试向量，不让未经校核的古法直接控制生产准确率。
- `clause-corpus`：底本、校勘、语义签名和授权信息。
- `rectification-engine`：候选分钟、似然、主动选条和停止规则。
- `ritual-session`：起数、启卷、应验、撤条和落刻状态机。
- `book-compiler`：按编号和年龄组织前运、今局与后程。

## 8. 新三轮 UI 迭代

### 第一轮：流程忠实度

- 完成入局、起数、启卷、应/不应、复算和落刻六个关键状态。
- 用 30–50 条固定测试条跑通，不追求完整命书。
- 验收重点：用户是否感觉在定出生刻分，而不是答问卷。

### 第二轮：移动端节律

- 优化单手操作、纵横排切换、字号、声音、震动和连续回答疲劳。
- 对 320×568、390×844、768×1024 三类视口做视觉校验。
- 验收重点：12–18 条连续交互仍有悬念，不重复、不拖沓。

### 第三轮：命书冲击力

- 完成落刻仪式、前运时间轴、原条/批注双层阅读和后程章节。
- 让用户能收藏、分享或打印命书，但页面不变成报告仪表盘。
- 验收重点：前运节点具体、后程断语明确、整书像命籍而不是 AI 总结。

## 9. 验收指标

### 流程认知

- 至少 80% 的测试用户能自然复述：“系统在通过条文确认我的出生刻分”。
- 少于 20% 的用户主动描述为“问卷、性格测试或套话”。

### 前运识别

- 硬事件 precision、recall 和节点时间误差分别统计。
- 六亲、迁移、婚姻、事业、财务等领域分开计分，不只给总准确率。
- 原条是否易懂与事实是否命中分开测量。

### 定刻稳定性

- 相同输入与相同回答必须得到相同数序轨迹和定刻结果。
- 轻微改动一条低权重回答时，不应造成大幅跳时。
- 删除任一封存确认条后，结果仍应落在同一四分钟区间。

### 体验

- 首次完成时长目标 6–10 分钟。
- 中途退出率、连续“不应”后的挫败率和“未明”占比单独监控。
- 落刻与命书开启应成为两个可测量的情绪峰值。

## 10. 实施顺序

1. 确认底本和扫描页版本。
2. 建立 30–50 条固定考刻条及完整来源字段。
3. 写出候选分钟与数序的确定性原型。
4. 用旧模拟真人框架重建 12–18 条考刻实验。
5. 先做三套单条页视觉靶图，选定后再改正式代码。
6. 完成三轮 UI 实现和视觉校验。
7. 扩充到 200–300 条考刻 MVP，并开始命书编纂实验。
