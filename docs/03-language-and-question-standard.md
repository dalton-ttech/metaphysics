# V3 条文与命书语言规范

## 1. 总原则

条文不是现代问卷句，也不是难读的纯文言。目标是：

- 一眼像签文、断语或旧籍条目；
- 普通用户不经训诂也能理解大意；
- 每条只承载一个可回答事实；
- 原文保留适量含混和意象；
- 白话解读给出清楚的时间、人物、事件边界。

## 2. 两层文本

### 条文层

长度建议 8—22 个汉字，半文半白，允许倒装、省略、年龄代称和经典意象。

示例：

- 未冠先别故土，生活另起。
- 少年家财一落，日用从此收束。
- 十岁上下，两换住处。
- 中岁以后，家门旧势再动。

### 司刻解

用现代白话解释唯一事实：

- 时间窗口；
- 涉及人物；
- 怎样才算“应”；
- 明确没有时答“不应”；
- 记不清时答“未明”。

司刻解默认折叠，不在主视觉中说明算法。

## 3. 单命题硬约束

每条考刻条必须满足：

1. 只有一个 primaryFactId；
2. 不能用“任一、至少一项、其中之一”等 OR 规则；
3. 不能把事业、婚姻、疾病等互不相同事件塞进同一句；
4. 时间修饰属于同一事实，不算第二事件；
5. 事件后果若只是定义的一部分，可以保留；若可独立回答，必须拆条；
6. 用户只需回答应、不应、未明。

## 4. 含混度

允许的含混：

- 用“未冠、二旬、中岁”代替精确年龄，但解读层必须给出范围；
- 用“故土、门户、旧局、关口”代替现代分类词；
- 用“有变、再动、另起”表达事件性质；
- 省略主语，但结构化事实必须有 subject。

不允许的含混：

- 同一句可以解释成三个不同事件；
- 纯氛围而没有可核验事实；
- 把事实概率、推荐算法或问题意图写进页面；
- 用“可能、也许、大概什么都算”逃避事件边界；
- 伪称古籍原文或某一传承秘本。

## 5. 命书结构

### 前尘

每个节点固定四层：

1. 年龄段 · 人物；
2. 领域 · 事件标题；
3. 原条；
4. 白话事件与后果。

原条营造沉浸，白话负责准确。不得把没有应验答案的候选事实写成既往经历。

### 后程

每个节点固定四层：

1. 年龄段；
2. 预言式判词或古诗句；
3. 一条可以观察的征兆；
4. 一句简明白话判断。

后程不设“身心调序”“财途归整”一类概念标题，也不另加重复的后果句。判词只使用一个中心意象；白话直说这一年龄段会发生什么。禁用“路径、结构、课题、能量、沉淀、赋能、重启、开启、新局”等报告式或 AI 式词语。

## 6. 消费者页面禁用词

- 第几题、共多少题、进度、完成百分比；
- 概率、后验、信息增益、码字、模型、Agent；
- 我们正在判断你的家庭 / 婚姻 / 健康；
- 候选画像、高置信层、召回率、准确率；
- Demo、说明、为什么显示这个元素。

这些内容只出现在研究、测试和后台文档。

## 7. 来源标注

所有 V3 条文数据必须保留：

- source.kind=modern_fabricated；
- 现代拟制·古籍断语体标签；
- 非古籍原文、非传承秘本的 provenance；
- 生成版本、事实 ID 和条文 ID。

用户界面不需要逐条展示工程来源，但内部和发布清单必须可审计。
