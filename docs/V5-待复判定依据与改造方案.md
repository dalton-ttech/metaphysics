# V5 待复判定依据与改造方案

## 结论

消费者页面原句“旧事证据尚不能区分相邻刻分，不启命籍”依据不足，现已删除。

现有引擎判断的是 120 个候选分钟的后验分布是否达到锁定阈值，并没有验证第一名与第二名必然相邻。因此，“相邻刻分”把算法没有证明的关系写进了界面。新版消费者页面只显示“诸数未归 / 命籍暂封”，内部改用原因码，不向用户展示概率或工程解释。

## 当前锁定闸门

候选集合覆盖一个时辰内的 120 个分钟。每次“应 / 不应”更新候选后验，再检查以下条件：

| 闸门 | 正合 | 已稳 |
|---|---:|---:|
| 最少问答 | 14 | 18 |
| 明确回答 | 11 | 14 |
| 第一候选后验 | ≥ 0.88 | ≥ 0.72 |
| 第一候选所在四分钟桶的后验总量 | ≥ 0.96 | ≥ 0.90 |
| 第一名与第二名后验差 | ≥ 0.28 | ≥ 0.14 |
| 覆盖事件领域 | ≥ 4 | ≥ 4 |
| 有命中的事件领域 | ≥ 2 | ≥ 2 |
| 回答完整性 | 是 | 是 |
| 末段旁证与首选画像相合 | 是 | 是 |

回答完整性还要求：至少两次“应”、至少两次“不应”、至少十个不同事实；连续同答不得超过九次；机械性交替不得锁定。问答上限为 24。达到上限仍未过闸门时，内部原因码为 `posterior_not_converged`。

## 现有依据的边界

1. “四分钟桶”只是把候选分钟按连续四个一组求和，不等于第一、第二候选相邻。
2. 后验概率是工程模型内的置信度，不是真人世界的准确率。
3. 当前末段旁证仍参与了后验更新，因此它是终止闸门，不是真正隔离的保留集验证。
4. 合成样本能审核码本可恢复性和异常回答拒绝能力，不能证明真实人生可由出生分钟恢复。

## 后续工程改造

1. **展示层隔离**：用户端只接收 `locked / pending-review` 状态；失败原因、概率和阈值只进入审核日志。
2. **精确失败码**：分别记录回答完整性不足、领域覆盖不足、四分钟桶未收敛、第一二名差距不足、题库耗尽，不再生成带推断色彩的自然语言原因。
3. **真实保留集**：末段预留一至两条旁证，在锁定前不参与后验更新；候选先收敛，再用旁证做独立复核。
4. **候选关系审计**：日志记录第一、第二候选的分钟距离、是否同一四分钟桶、各自后验与差值。只有计算过距离，内部报告才可使用“相邻”一词。
5. **模拟验收**：继续覆盖 120 个密封候选、一处记忆误差、全应、全不应、全未明、机械交替，并新增“后验高但保留集不合”与“第一二名跨桶相持”的拒绝用例。

本阶段的产品规则是：锁定必须有可审计的数值依据；未锁定只呈现仪式状态，不在消费者页面解释算法。
